# Brief สำหรับ Claude Code: แพลตฟอร์มแผนที่ตรวจที่ดิน กรุงเทพฯ และปริมณฑล

10 ต.ค. 2569 · @Kanesuan

## 1. ภาพรวม

สร้างเว็บแอปแผนที่เต็มจอให้คนซื้อขายที่ดินในกรุงเทพฯ และปริมณฑลเปิดปิดชั้นข้อมูลผังเมืองและภัยพิบัติ แล้วแตะจุดใดก็ได้เพื่ออ่านคำอธิบายเป็นภาษาที่คนทั่วไปเข้าใจ

- ผู้ใช้: คนทั่วไปที่กำลังจะซื้อหรือขายที่ดิน ไม่มีพื้นฐาน GIS หรือผังเมือง และส่วนใหญ่เปิดจากมือถือ
- พื้นที่: กรุงเทพมหานครก่อน แล้วขยายไปนนทบุรี ปทุมธานี สมุทรปราการ นครปฐม และสมุทรสาคร ตัวแผนที่ครอบคลุมทั้งหกจังหวัดตั้งแต่วันแรก
- MVP ต้องทำได้สามอย่าง: ดูแผนที่และค้นหาสถานที่ เปิดปิด layer พร้อมคำอธิบายสัญลักษณ์ และแตะจุดเพื่อดูว่าจุดนั้นอยู่ในเขตอะไร
- เป้าหมายการออกแบบ: ผู้ใช้ใหม่เปิด layer แรกและอ่านผลของหนึ่งจุดได้ภายใน 30 วินาที โดยไม่ต้องอ่านคู่มือ

เอกสารนี้คือ brief ทั้งหมดที่ Claude Code ต้องใช้ ให้บันทึกไว้ใน repo เป็น docs/BRIEF.md ส่วนที่ 8 และ 10 คัดลอกไปใช้ได้ทันที

## 2. ขอบเขตของ MVP

MVP มีหน้าเดียว คือแผนที่เต็มจอที่เปิดปิด layer และแตะดูข้อมูลได้ ไม่มีระบบสมาชิกและไม่มีการชำระเงิน

### ทำในรอบนี้

- แผนที่เต็มจอ ย่อขยาย เลื่อน และปุ่มตำแหน่งของฉัน
- ช่องค้นหาสถานที่ และรับพิกัดแบบ `13.7563, 100.5018`
- แผง layer: เปิดปิด ปรับความโปร่งใส คำอธิบายสัญลักษณ์ แหล่งข้อมูล และวันที่ของข้อมูล
- แตะจุดบนแผนที่เพื่อดูสรุปของทุก layer ที่จุดนั้น
- ลิงก์แชร์ได้: URL เก็บตำแหน่ง ระดับซูม และ layer ที่เปิดอยู่
- ใช้งานได้ทั้งมือถือและเดสก์ท็อป ข้อความบนหน้าจอเป็นภาษาไทย

### ไม่ทำในรอบนี้

- สมัครสมาชิก เข้าสู่ระบบ และชำระเงิน
- รายงาน PDF รายแปลง และการเลื่อนเทียบผังปัจจุบันกับร่างผังใหม่ (เฟสถัดไป)
- รูปแปลงโฉนดและเลขโฉนด ห้ามดึงข้อมูลจาก LandsMaps หรือเว็บไซต์รัฐด้วยการ scrape
- การประเมินราคาที่ดิน
- แอป native และหน้าจัดการ layer สำหรับผู้ดูแล (เพิ่ม layer ผ่าน config และสคริปต์แทน)

## 3. หน้าจอและการใช้งาน

แผนที่กินพื้นที่ทั้งหน้าจอเสมอ ส่วนควบคุมทุกอย่างลอยอยู่บนแผนที่และพับเก็บได้ ตัวหน้าเว็บไม่มีการเลื่อนขึ้นลง

บนเดสก์ท็อป แผงชั้นข้อมูลอยู่ทางซ้ายและผลของจุดที่แตะเปิดทางขวา บนมือถือ แผงชั้นข้อมูลย่อเป็นปุ่ม และผลของจุดเลื่อนขึ้นจากด้านล่าง

| ส่วน | เดสก์ท็อป | มือถือ (กว้างไม่เกิน 768px) | หน้าที่ |
|---|---|---|---|
| แผนที่ | เต็มจอ | เต็มจอ | ย่อขยาย เลื่อน แตะเพื่อดูข้อมูลของจุด |
| ช่องค้นหา | ซ้ายบน เหนือแผง layer | บนสุด เต็มความกว้าง | ค้นหาชื่อสถานที่หรือพิกัด แล้วเลื่อนแผนที่ไป |
| แผง layer | ซ้าย กว้าง 320px พับได้ | แผ่นเลื่อนจากล่าง เปิดด้วยปุ่ม "ชั้นข้อมูล" | เปิดปิดและปรับ layer |
| แผงผลของจุด | ขวา กว้าง 360px ปิดได้ | แผ่นเลื่อนจากล่าง สูงครึ่งจอ ลากขึ้นเต็มจอได้ | แสดงสรุปของจุดที่แตะ |
| ปุ่มควบคุมแผนที่ | ขวาล่าง | ขวาล่าง เหนือแผ่นเลื่อน | ซูม ตำแหน่งของฉัน สลับแผนที่ฐาน |

### แผง layer

- จัดเป็นสี่กลุ่ม: ผังเมือง ภัยพิบัติ โครงสร้างพื้นฐาน และขอบเขตการปกครอง
- แต่ละแถวมีสวิตช์เปิดปิด ชื่อ layer และคำอธิบายหนึ่งบรรทัด
- เมื่อเปิด layer แถวจะขยายแสดงแถบปรับความโปร่งใส สัญลักษณ์สี ชื่อหน่วยงานเจ้าของข้อมูล และวันที่ของข้อมูล
- layer ที่ทับกันสนิท เช่น ผังปัจจุบันกับร่างผังใหม่ เปิดได้ทีละชั้น
- layer ที่ยังใช้ข้อมูลตัวอย่างมีป้าย "ข้อมูลตัวอย่าง" ส่วนร่างผังมีป้าย "ร่าง ยังไม่บังคับใช้"
- สถานะกำลังโหลดและโหลดไม่สำเร็จแสดงในแถวของ layer นั้น พร้อมปุ่มลองใหม่

### เมื่อแตะจุดบนแผนที่

1. ปักหมุดที่จุดนั้นและเปิดแผงผล
2. แผงผลแสดงหนึ่งการ์ดต่อ layer ที่ตอบได้ ไม่ว่า layer นั้นจะเปิดอยู่หรือไม่ โดย layer ที่เปิดอยู่ขึ้นก่อน
3. แต่ละการ์ดมีชื่อ layer คำตอบเป็นประโยคภาษาคน เช่น "ที่ดินประเภทที่อยู่อาศัยหนาแน่นน้อย (ย.3)" และปุ่ม "ดูบนแผนที่" ที่เปิด layer นั้น
4. ท้ายแผงมีข้อความ "ข้อมูลเพื่อการตรวจสอบเบื้องต้น ไม่ใช่เอกสารทางกฎหมาย โปรดยืนยันกับหน่วยงานที่เกี่ยวข้องก่อนตัดสินใจ"

### หลักการออกแบบ

- ครั้งแรกที่เข้า เปิด layer ผังเมืองปัจจุบันไว้หนึ่งชั้น และมีคำใบ้หนึ่งบรรทัดที่ปิดได้: "แตะที่แผนที่เพื่อดูข้อมูลของจุดนั้น"
- สีผังเมืองใช้ตามข้อมูลต้นทางและมาตรฐานผังเมืองรวม: ที่อยู่อาศัยเหลือง ส้ม น้ำตาล พาณิชยกรรมแดง อุตสาหกรรมม่วง เกษตรกรรมเขียว สถาบันราชการน้ำเงิน
- สีของ layer ภัยพิบัติต้องแยกออกได้สำหรับผู้ที่ตาบอดสี
- ปุ่มและสวิตช์ทุกตัวมีพื้นที่แตะอย่างน้อย 44×44px และใช้คีย์บอร์ดได้
- ตัวอักษรเนื้อหาไม่เล็กกว่า 16px บนมือถือ

## 4. Tech stack และโครงสร้างโปรเจกต์

MVP เป็นเว็บแอป Next.js ที่ไม่มีฐานข้อมูล ข้อมูล layer เป็นไฟล์ static และมี API route เดียวไว้เรียกบริการภายนอกโดยไม่เปิดเผย key

ผังเมืองและรถไฟฟ้าถูกแปลงเป็นไฟล์ static ก่อน deploy ส่วนน้ำท่วมซ้ำซากถูกเรียกสดผ่าน /api/inspect ทุกครั้งที่ผู้ใช้แตะจุด

| ส่วน | เลือกใช้ | เหตุผล |
|---|---|---|
| Framework | Next.js (App Router) และ TypeScript แบบ strict | หน้าเว็บกับ API route อยู่ในโปรเจกต์เดียว |
| แผนที่ | MapLibre GL JS | โอเพนซอร์ส ไม่ต้องมี token รองรับ vector tiles และ layer จำนวนมาก |

| UI | Tailwind CSS และ Radix UI | สวิตช์ แถบเลื่อน และแผ่นเลื่อนที่ใช้คีย์บอร์ดและ screen reader ได้ |

## 5. Layer registry และข้อมูล

layer ทุกชั้นประกาศไว้ที่เดียวใน src/layers/registry.ts การเพิ่ม layer ใหม่คือเพิ่มหนึ่งรายการกับไฟล์ข้อมูลหนึ่งไฟล์ โดยไม่ต้องแก้ component ใดเลย

```ts
import type { LayerSpecification } from "maplibre-gl";

export type LayerGroup = "zoning" | "hazard" | "infrastructure" | "boundary";

export type LayerSource =
  | { kind: "pmtiles"; url: string; sourceLayer: string }
  | { kind: "geojson"; url: string }
  | { kind: "api"; endpoint: string }; // ตอบเฉพาะตอนแตะจุด ไม่วาดบนแผนที่

export type LayerConfig = {
  id: string;                    // เช่น "bkk-zoning-current"
  group: LayerGroup;
  name: string;                  // key ใน i18n
  summary: string;               // key ใน i18n คำอธิบายหนึ่งบรรทัด
  source: LayerSource;
  style: LayerSpecification[];   // ว่างได้เมื่อ kind เป็น "api"
  legend: { color: string; label: string }[];
  defaultVisible: boolean;
  defaultOpacity: number;        // 0 ถึง 1
  exclusiveGroup?: string;       // layer ที่มีค่าเดียวกันเปิดได้ทีละชั้น
  badge?: "sample" | "draft";
  inspect?: {
    title: string;
    describe: (props: Record<string, unknown>) => string | null;
  };
  attribution: {
    org: string;
    url: string;
    license: string;
    dataDate: string;            // YYYY-MM-DD
    commercialUse: "yes" | "no" | "unverified";
  };
  status: "live" | "sample";
  coverage: string[];            // รหัสจังหวัด เช่น ["10"] คือกรุงเทพมหานคร
};
```

### layer ชุดแรก

| id | ชื่อที่แสดง | กลุ่ม | แหล่งข้อมูล | เริ่มต้นด้วย | สิทธิ์ใช้งาน |
|---|---|---|---|---|---|
| bkk-zoning-current | ผังเมืองรวม กทม. ที่บังคับใช้ | ผังเมือง | บริการแผนที่ กฎหมายผังเมือง ของ กทม. ชั้น 1 แผนผังข้อกำหนดการใช้ประโยชน์ที่ดิน | ข้อมูลตัวอย่าง เปลี่ยนเป็นข้อมูลจริงใน M4 | ยังไม่พบการระบุสัญญาอนุญาต ต้องขออนุญาตก่อน |
| bkk-zoning-draft4 | ร่างผังเมืองรวม กทม. ปรับปรุงครั้งที่ 4 | ผังเมือง | สำนักการวางผังและพัฒนาเมือง กทม. ยังไม่พบไฟล์ให้ดาวน์โหลด | ข้อมูลตัวอย่าง | ต้องขอไฟล์และสิทธิ์ |
| bkk-planned-roads | โครงการถนนตามผังเมือง | โครงสร้างพื้นฐาน | บริการเดียวกัน ชั้น 4 และ 5 แผนผังแสดงโครงการคมนาคมและขนส่ง | ข้อมูลตัวอย่าง เปลี่ยนเป็นข้อมูลจริงใน M4 | เช่นเดียวกับผังเมือง |
| flood-recurrence | น้ำท่วมซ้ำซาก 2011–2023 | ภัยพิบัติ | GISTDA Open Data API flood-recurrence | ข้อมูลจริง ตอบเมื่อแตะจุด | Open Data Common ต้องมี API key |
| subsidence | แผ่นดินทรุด | ภัยพิบัติ | ยังไม่มีแหล่งข้อมูลเปิดที่ยืนยันได้ | ข้อมูลตัวอย่าง | ต้องหาแหล่งข้อมูล |
| rail-transit | รถไฟฟ้าและสถานี | โครงสร้างพื้นฐาน | OpenStreetMap | ข้อมูลจริง | ODbL ต้องแสดงที่มา |
| admin-boundary | ขอบเขตจังหวัดและเขต | ขอบเขตการปกครอง | ชุดขอบเขตการปกครองแบบเปิด เช่น COD-AB บน HDX | ข้อมูลจริง | บันทึกสัญญาอนุญาตของชุดที่เลือก |

### รายละเอียดทางเทคนิคของแหล่งข้อมูล

- บริการแผนที่ของ กทม. ใช้พิกัด EPSG:32647 ตอบ query เป็น JSON, GeoJSON หรือ PBF และคืนสูงสุด 1,000 รายการต่อคำขอ สคริปต์ ingest ต้องแบ่งหน้าด้วย resultOffset แล้วแปลงพิกัดเป็น EPSG:4326
- GISTDA: `GET https://api-gateway.gistda.or.th/api/2.0/resources/gi-service/v1.1/disasters/flood-recurrence` รับ lat, lon และ api_key หรือรับ area เป็น GeoJSON Feature แทนพิกัด หน้าชุดข้อมูลมีทั้ง v1.0 และ v1.1 ให้ยืนยันเวอร์ชันจากเอกสารของ API gateway
- ห้ามเดาโครงสร้างคำตอบของ API ให้เรียกจริงหนึ่งครั้ง เก็บคำตอบเป็น fixture ใน tests/ แล้วเขียน parser ที่มี type กำกับ

### กติกาของข้อมูล

- ทุก layer ต้องกรอก attribution ครบ และแผง layer ต้องแสดงชื่อหน่วยงานกับวันที่ของข้อมูลเสมอ
- ข้อมูลตัวอย่างคือ polygon สมมติภายในขอบเขตกรุงเทพฯ ตั้งชื่อไฟล์ลงท้าย .sample.geojson กำหนด status: "sample" และแสดงป้าย "ข้อมูลตัวอย่าง" ทั้งในแผง layer และการ์ดผล
- คำสั่ง `npm run check:layers` ต้องทำให้ production build ล้ม เมื่อมี layer ที่ status เป็น live แต่ commercialUse ไม่ใช่ yes
- ไม่ใช้ชุดพื้นที่เสี่ยงน้ำท่วมรายตำบลของ สสน. เพราะเป็นสัญญาอนุญาตแบบห้ามใช้เชิงพาณิชย์

## 7. เกณฑ์ตรวจรับและการทดสอบ

งานถือว่าเสร็จเมื่อผ่านทุกข้อด้านล่างบน URL ที่ deploy แล้ว ไม่ใช่เฉพาะบนเครื่องพัฒนา

### การใช้งาน

- แผนที่เต็มพื้นที่จอที่ 360×640, 768×1024 และ 1440×900 โดยหน้าเว็บไม่มี scrollbar
- เปิดปิด layer แล้วแผนที่เปลี่ยนภายใน 1 วินาทีเมื่อข้อมูลถูกโหลดไว้แล้ว
- คัดลอก URL ไปเปิดในแท็บใหม่แล้วได้ตำแหน่ง ระดับซูม และ layer ชุดเดิม
- แตะจุดในกรุงเทพฯ แล้วได้การ์ดผลภายใน 2 วินาที จุดที่ไม่มีข้อมูลแสดงข้อความ "ไม่มีข้อมูลในจุดนี้"
- บนมือถือ แผ่นเลื่อนของแผง layer และแผงผลลากขึ้นลงได้ และไม่บังปุ่มควบคุมแผนที่
- ใช้แผง layer ได้ครบด้วยคีย์บอร์ดอย่างเดียว และสวิตช์ทุกตัวมีชื่อให้ screen reader อ่าน

### ข้อมูลและความปลอดภัย

- ทุก layer แสดงหน่วยงานเจ้าของข้อมูลและวันที่ของข้อมูล layer ตัวอย่างและร่างผังมีป้ายกำกับ
- ค้นหาใน build output แล้วไม่พบค่า GISTDA_API_KEY
- npm run check:layers ผ่าน และล้มจริงเมื่อทดลองตั้ง layer ที่ยังไม่ยืนยันสิทธิ์เป็น live
- เมื่อ API ภายนอกล่ม การ์ดของ layer นั้นแสดงว่าโหลดไม่สำเร็จ ส่วน layer อื่นยังทำงานปกติ

### คุณภาพและความเร็ว

- npm run lint, typecheck, test, test:e2e และ build ผ่านใน CI ทุก PR
- Lighthouse หมวด Performance บนโปรไฟล์มือถือได้ไม่ต่ำกว่า 80 และหมวด Accessibility ไม่ต่ำกว่า 90
- unit test ครอบคลุมการตรวจ registry การเข้ารหัสและถอดรหัสสถานะใน URL และฟังก์ชัน describe ทุกตัว
- end-to-end test ครอบคลุมสี่เส้นทาง: โหลดแผนที่ เปิดปิด layer แตะจุดแล้วเห็นการ์ดผล และใช้แผ่นเลื่อนบนจอขนาดมือถือ

## 8. กติกาการทำงานสำหรับ Claude Code

## 10. ข้อความเริ่มงาน

วางไฟล์สองไฟล์ลงใน repo ก่อน แล้วส่งข้อความด้านล่างให้ Claude Code เป็นข้อความแรก

1. บันทึกเนื้อหาของเอกสารนี้เป็น docs/BRIEF.md
2. บันทึกข้อความในส่วนที่ 8 เป็น CLAUDE.md ที่ root ของ repo
3. เปิด Claude Code ในโฟลเดอร์ของ repo แล้ววางข้อความนี้

```
อ่าน docs/BRIEF.md ให้ครบก่อน แล้วทำตามลำดับนี้

1. สรุปกลับมาไม่เกิน 10 บรรทัดว่าต้องสร้างอะไร และชี้ข้อใน brief
   ที่ยังกำกวมหรือขัดกันเอง
2. เสนอแผนของ M0 เป็นรายการไฟล์ที่จะสร้างและคำสั่งที่จะรัน
   แล้วรอให้ฉันยืนยัน
3. เมื่อฉันยืนยันแล้ว ทำ M0 ให้เสร็จ รัน lint, typecheck, test และ build
   รายงานผล แล้วเปิด PR
4. หยุดหลังจบ M0 อย่าเริ่ม M1 จนกว่าฉันจะสั่ง

ข้อที่ห้ามละเมิด
- แผนที่ต้องเต็มจอเสมอ และ layer ทุกชั้นประกาศใน
  src/layers/registry.ts เท่านั้น
- ใช้ข้อมูลตัวอย่างจนกว่าฉันจะยืนยันสิทธิ์ใช้ข้อมูลจริงของแต่ละ layer
- ห้าม scrape เว็บไซต์รัฐหรือ LandsMaps
- ห้ามใส่ key ลงในโค้ดหรือใน commit
```
